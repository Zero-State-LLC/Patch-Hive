# 009 Tasks: Photo to Patch Book

Each task is a ticket sized for one fresh context window. **AFK** tickets are fully specified, so an agent can take one away from the keyboard. **HITL** tickets need a person. Each ticket's contract is [spec.md](spec.md); this file holds only the order and what done means. A task that pairs code with an operator action is split: `a` is the code, `b` the operator action. `scripts/check_spec_dag.py` checks this file.

- [x] T022 (AFK) The NVIDIA prompt and parser through the Clef adapter return every Sighting in one whole-rig answer, bounded to five candidates each. Done when the adapter's tests pass on recorded answers, including malformed and oversized ones. It needs no live call. Done 2026-11-07: `evidence/nvidia_reading.py` (`NvidiaRigReader`) sends the stored photo once, with a JSON schema bounded to 200 Sightings of at most five candidates, and steps through the Clef adapter's states. The model can't know catalog ids, so it names each candidate by maker and model, and `CatalogNames` resolves the names, ignoring case, spaces and punctuation (letters in any script count): the name must be a Module's, and the maker its brand or the start of it, so "Mutable" finds "Mutable Instruments"; a candidate matches only when exactly one Module fits. A name the catalog lacks, one two Modules fit, or a tombstoned Module's is dropped, never guessed; two names for one Module add up; a Sighting left with none stays unresolved. NVIDIA reads only with `enable_nvidia_provider` on (`PROVIDER_DISABLED`) and a key (`PROVIDER_NOT_CONFIGURED`), so `PROVIDER_UNAVAILABLE` is gone, and only a photo whose owner agreed: the photo start now takes `consent_provider_processing` (default false), and a Reading of a photo without it fails `CONSENT_NOT_GRANTED` before anything is sent. A whole Rig's answer gets `photo_reading_timeout_seconds` (120), not the one-Module timeout. A box that overshoots the photo's edge by at most 0.02 is trimmed to it. It fails a Reading with `PROVIDER_TIMED_OUT`, `PROVIDER_ERROR` (transport or refused call), `ANSWER_MALFORMED`, `TOO_MANY_SIGHTINGS`, `TOO_MANY_CANDIDATES`, `PHOTO_TOO_LARGE` (past the adapter's 4 MB) or `PHOTO_UNREADABLE`, and only the code leaves.

- [x] T031 (AFK) Retry and Retake, so a failed Reading can't block its Rig. Retry (`POST /api/racks/{id}/evidence/readings/{reading_id}/retry`) reads a `failed` Reading's stored photo again as a new Reading and marks the old one `superseded`. It is refused with `PHOTO_EXPIRED` when the photo has expired or been deleted, with `READING_NOT_FAILED` for any other status, and with `PHOTO_READING_UNAVAILABLE` while reading is closed. Retake is the photo start with `replaces_reading_id`, which supersedes that current Reading of the same Rig. Confirming ignores `superseded` Readings, keeps Placements on rows no current Reading covers, and replaces only the covered rows; the overlap and Case checks run across the whole resulting Rig. Done when API tests cover a retry after a failed Reading, a retry refused on an expired photo, a retake, and a later photo of one row leaving the other rows' Placements in place. Done 2026-11-07: retry refuses in this order: `READING_NOT_FOUND` (404) for a Reading not on the Rig, `PHOTO_READING_UNAVAILABLE`, `READING_NOT_FAILED`, then `PHOTO_EXPIRED` (all 409). A retake also needs `rig_id` (`RETAKE_NEEDS_RIG`, 400), and refuses a Reading that isn't `read` or `failed` with `READING_NOT_REPLACEABLE`; nothing is stored when it refuses. Superseding is a conditional update, so two requests can't both replace one Reading; confirming uses the same update, and refuses with `READINGS_CHANGED` when a Retake or Retry got there first. A stored photo whose bytes no longer match counts as expired. A Module added by hand may go on an uncovered row; the overlap check then runs against the Placements kept there. The inventory revision lists the whole Rig, and a kept Placement keeps its jumper setting.
