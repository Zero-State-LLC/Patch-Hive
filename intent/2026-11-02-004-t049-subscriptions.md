# Intent

## Problem

Spec 004 Machine C (subscriptions, T049) does not exist. `customer.subscription.*` events are `unresolved` (`HANDLER_NOT_IMPLEMENTED`), a subscription-mode Checkout Session is `unresolved` too, `invoice.paid` is `ignored`, and there is no subscription record, no per-period grant, no cancel route and no STUDIO entitlement (FR-003, FR-004, FR-015–FR-018). The open questions T049 needs were decided 2026-11-01 by Jev (owner-delegated): OQ-1 provisional prices and credits, OQ-3 `A_both`, OQ-4 `A_stripe_mapping`, OQ-7 `A_next_period_no_proration`, OQ-8 `A_flag_with_fair_use`, and OQ-13 `D_defer_sales` (everything stays behind flags, off).

## Proposed outcome

- **Checkout (`choose_tier`).** `start_subscription_checkout` and `POST /api/canon/checkout/subscription` (`tier`: `core`, `pro` or `studio`) open a `subscription`-mode Checkout Session for the tier's configured price. Behind its own flag `ENABLE_SUBSCRIPTION_CHECKOUT` (default false) and `checkout_gate`'s other refusals (production without `ALLOW_PRODUCTION_PAYMENTS`, missing key, live key). A tier with no configured price is 503 `SUBSCRIPTION_PRICE_MISSING`. A user with a live (not `canceled` or `incomplete_expired`) subscription, or a paid checkout whose subscription has not arrived, is 409 `SUBSCRIPTION_EXISTS`. No subscription record is written at checkout (an abandoned checkout leaves none). A `SubscriptionCheckoutRecord` reserves checkout per user under a user row lock: a repeated request for the same tier reuses the open session, another tier is 409 `SUBSCRIPTION_CHECKOUT_OPEN`, until the session's `expires_at` (1 hour) passes or `checkout.session.expired` arrives (Codex review on #219).
- **Price to tier.** Only through settings: `SUBSCRIPTION_PRICE_ID_CORE`, `_PRO`, `_STUDIO` (empty by default). A price configured for two tiers maps to none.
- **Subscription record.** `ProviderSubscriptionRecord`, one per provider subscription id: tier (from the provider price, OQ-7), provider status (stored verbatim; OQ-4 entitlement mapping is T050), current period, `cancel_at_period_end`, the newest applied event's `created` time, `purchase_recorded_at`, `canceled_at`. `customer.subscription.created`/`updated` only sync it and never grant. An older event delivered late is `duplicate` (`STALE_EVENT`); an event that changes nothing is `duplicate` (`SUBSCRIPTION_UNCHANGED`). `customer.subscription.deleted` sets `canceled`, which is final: later events are `duplicate` (`SUBSCRIPTION_ALREADY_CANCELED`). Credits already granted stay.
- **Period grant (`invoice.paid` only).** One `SubscriptionPeriodGrantRecord` per period, keyed `subscription-period:<subscription_id>:<period_start>`, unique on the key, the invoice and (subscription, period start). The period and tier come from the invoice's one priced line (its `period` is the service period). CORE and PRO append one canonical `grant` entry with the tier's credits (`SUBSCRIPTION_CREDITS_CORE` 25, `SUBSCRIPTION_CREDITS_PRO` 100) and the same key. A repeat for a granted period is `duplicate` (`PERIOD_ALREADY_GRANTED`). The subscription row lock serializes concurrent deliveries; the unique keys back it. An `invoice.paid` that arrives before the subscription event creates the record as `active` (EC-2).
- **STUDIO (OQ-8).** No credits and no numeric sentinel (FR-004). The period grant carries `unlimited = true` and `fair_use_export_cap`, copied from `SUBSCRIPTION_STUDIO_FAIR_USE_EXPORTS_PER_PERIOD` when granted. The default 100 exports per period is conservative: at one credit or more per export it allows no more than PRO's 100 credits. The owner sets the real value. Spending against the entitlement (export without a debit, up to the cap) is T050 / the export path, not here.
- **Referral (OQ-3 `A_both`).** The subscription's first paid invoice also calls `record_purchase(payment_verified=True, credits_delta=0)`. The legacy `Purchase` row is the Machine A marker; the period credits are the separate canonical grant.
- **Unresolved, nothing written.** Unknown customer (`CUSTOMER_NOT_FOUND`), subscription owned by another customer (`CUSTOMER_MISMATCH`), unmapped price (`PRICE_UNKNOWN`), more than one item or priced line, unknown status, malformed period, metadata naming another user, an invoice that is not paid, not for a subscription, or for zero (`INVOICE_AMOUNT_ZERO`), and an invalid tier setting (`TIER_CONFIG_INVALID`).
- **Subscription-mode Checkout Session events** only settle the reservation (`completed` with its subscription id, or `expired`); otherwise `ignored` (`SUBSCRIPTION_SESSION_NO_EFFECT`).
- **Stale-event watermark.** A newer event advances `last_event_created` even when it changes nothing, so a delayed older snapshot cannot roll the record back (Codex review on #219).
- **Cancel (`cancel_requested`, FR-017).** `request_subscription_cancel` and `POST /api/canon/subscription/cancel` set `cancel_at_period_end=true` at the provider and locally for the user's `active` subscription. Already flagged: no provider call. 404 `SUBSCRIPTION_NOT_FOUND`, 409 `SUBSCRIPTION_NOT_ACTIVE`.
- **Operator resolve (T048b)** keeps returning 409 `RESOLVE_NOT_SUPPORTED` for Machine C: subscription and invoice events, and a subscription-mode session left unresolved before this change. An operator rejects them.
- Migration `20261102_subscriptions` (revises `20261102_purchase_refunds`, single head): three additive tables (`provider_subscriptions`, `subscription_period_grants`, `subscription_checkouts`); downgrade refuses while either has rows.

Out of scope: T050 (tier resolution from the subscription and spending the STUDIO entitlement), subscription invoice refunds and disputes, `invoice.payment_failed`, frontend, flag changes.

## Affected users / systems

Webhook processor (`canon/webhook_events.py`), Machine B (`canon/checkout.py`: `checkout_gate` takes the flag name; subscription-mode sessions; resolve), new `canon/subscriptions.py`, `canon/routes.py`, `canon/models.py`, `core/config.py`, the canonical ledger and the legacy `credits_ledger` (one `Purchase` marker per subscription).

## Constraints / non-goals

`ENABLE_SUBSCRIPTION_CHECKOUT=false`, `STRIPE_TEST_MODE=true`, `ALLOW_PRODUCTION_PAYMENTS=false` by default; no price ids are configured. Tests use fakes, `httpx.MockTransport` and signed fixture events: no network, no keys. The ledger and period grants are append-only. Not legal advice: OQ-13 needs counsel before any sale.

## Open questions

- Owner: the STUDIO fair-use cap value (default 100 exports per period) and whether its unit is exports (assumed from the decision's example) or credits.
- Owner: `SUBSCRIPTION_EXISTS` (one live subscription per user) is inferred from "my subscription" in the spec, not stated.
- Owner: cancel only from provider status `active` (the table's Active row); a `past_due` subscriber cannot cancel here.
- Owner: a zero-amount `invoice.paid` is `unresolved` (PatchHive sells no trials or full discounts).
- Owner: an `invoice.paid` for an already `canceled` subscription still grants its period (the payment was verified).
- Owner: the legacy `Purchase` marker carries 0 credits (Machine B mirrors credits there).
